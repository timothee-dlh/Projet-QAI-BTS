    \subsection{Histoire de l'entreprise}
    En 1955, Oswald Hager et Hermann Hager (1928-2014)créent avec leur père Peter Hager l’entreprise Hager oHG, elektrotechnische Fabrik, à Ensheim (Allemagne). À cette époque et depuis 1945, la Sarre est économiquement rattachée à la France et le marché allemand n'est pas accessible. Hager souhaite néanmoins s'implanter sur ces deux marchés.\newline
    \vspace{0.5cm}
    \newline
    En 1959, la famille Hager crée à Obernai, en Alsace, l’entreprise Hager Electro SA qui est la première filiale étrangère. À partir de 1966, Hager forme des installateurs électriciens de manière systématique ce qui instaure une culture de fidélisation des clients en leur fournissant des informations utiles. Le disjoncteur modulaire de Hager est breveté en Allemagne en 1968 puis en France en 1970. Dans le même temps, le premier tableau électrique en série, le « Hager-Rapid-System », fait son apparition sur le marché français. En 1973, Hager réalise un chiffre d'affaires de 43 millions de deutsche marks en Allemagne, et, en 1974, de 22 millions de francs en France.
    \vspace{0.5cm}
    \newline
    En 1976, Hager introduit sur le marché le petit coffret de distribution Gamma. Puis, en 1982, débute la production de disjoncteurs différentiels. Un nouveau site de production avec un entrepôt à hauts rayonnages est également créé à Blieskastel. Dans les années 1980, le groupe Hager commence à se positionner comme un fournisseur de services complets pour les installations électriques dans les bâtiments. Des sociétés de distribution sont créées en Europe (Suisse, Grande-Bretagne). Depuis le milieu des années 1990, le groupe Hager a développé son réseau de distribution aux Émirats arabes unis (Dubaï), à Singapour, en Malaisie, à Hong Kong, en Chine, en Australie et en Nouvelle-Zélande.
    \vspace{0.5cm}
    \newline
    Par la suite, de nombreuses acquisitions d'entreprises par HagerGroup permettent une diversification des activitées et assurent ainsi la prospérité du groupe.

        \section{Projet E6}
        \subsection{Gestion de projet}
        L’objectif de ce projet est de pouvoir mesurer la qualité de l’air des usines ainsi que d’envoyer des alertes si des seuils sont dépassés. 
        \newline
        Pour cela, un capteur de qualité d’air sera relié à un microcontrôleur qui va se charger de récupérer les données. Il va ensuite s'authentifier et les envoyer au broker MQTT hébergé sur le serveur Linux. \newline
Le serveur Linux va ensuite récupérer les informations, les stocker dans une base de données, les afficher sur une Dashboard et envoyer des alertes si besoin.

        \subsubsection{Diagramme de contexte :}
Le capteur de QAI effectue des mesures à intervalle régulier, ces mesures sont transmises au microcontrôleur ESP32 qui les transmet à son tour au serveur. Le serveur traite les données, les stocke et les affiche sur une Dashboard. \newline 
La Dashboard est accessible par les utilisateurs pour visualiser les données et par les administrateurs pour configurer le système.

        \subsubsection{Structure interne de la base de données}

        Cette base de données contient quatre tables : "capteur1", "capteur2", "capteur3" et "capteur4". \newline
        Chaque table a les colonnes suivantes :

        \begin{itemize}
            \item \textbf{id} : Identifiant unique.
            \item \textbf{nom\_capteur} : Nom du capteur.
            \item \textbf{valeur} : Valeur mesurée.
            \item \textbf{timestamp} : Horodatage de la mesure.
        \end{itemize}
        Chaque table stocke des données de capteurs différents avec une structure identique.

        \subsubsection{Code de conversion des données de la base de données pour l'affichage}
        Les données sont ensuite affichées dans un graphique montrant l'historique des mesures.
        \vspace{0.5cm}
        \begin{lstlisting}[style=javascript, caption={Code Javascript de transformation des données de la base de données pour l'affichage dans les graphiques de l'interface utilisateur}]
    // Récupérer les résultats de la requête MySQL
    let data = msg.payload;

    // Créer un tableau pour stocker les résultats formatés
    let formattedData = [];

    // Parcourir chaque ligne de données
    data.forEach(row => {
        // Chaque ligne a une valeur et un timestamp
        let point = {
            "x": new Date(row.timestamp).getTime(),  // Convertir le timestamp en millisecondes
            "y": row.valeur                    // La valeur associée
        };
        
        // Ajouter le point au tableau formaté
        formattedData.push(point);
    });

    // Envoyer les données formatées vers le graphique
    msg.payload = [{
        "series": ["Valeurs"],
        "data": [formattedData],
        "labels": ["Timestamp"]
    }];

    return msg;
        \end{lstlisting}
        \vspace{0.5cm}
Ce code JavaScript, utilisé dans un nœud Node-RED, transforme les résultats d'une requête MySQL pour les adapter à un graphique.\newline Il extrait les données de `msg.payload` et les reformate en objets avec des timestamps convertis en millisecondes et des valeurs associées.\newline Ces objets sont stockés dans un tableau `formattedData`.\newline Ensuite, les données formatées sont structurées dans `msg.payload` avec des séries, des données et des labels, puis renvoyées pour être utilisées par un nœud de visualisation graphique.

`id` INT NOT NULL AUTO_INCREMENT,
`nom_capteur` VARCHAR(45) NOT NULL,
`valeur` DECIMAL(10, 2),
`timestamp` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
PRIMARY KEY (`id`)
);

        Cette requête SQL crée une table nommée \texttt{capteur1} dans la base de données \texttt{projet-db}.\newline La table est conçue pour stocker des informations relatives à un capteur.\newline Elle contient quatre colonnes : \texttt{id}, \texttt{nom\_capteur}, \texttt{valeur}, et \texttt{timestamp}.\newline La colonne \texttt{id} est définie comme une clé primaire avec auto-incrémentation, assurant un identifiant unique pour chaque entrée.\newline \texttt{nom\_capteur} est une chaîne de caractères de 45 caractères maximum et ne peut pas être nulle, représentant le nom du capteur.\newline \texttt{valeur} est un nombre décimal avec une précision de 10 chiffres, dont 2 décimales, pour stocker les mesures du capteur.\newline Enfin, \texttt{timestamp} enregistre automatiquement la date et l'heure de création de chaque entrée, utilisant par défaut l'heure actuelle.\newline Cette structure permet de suivre et d'enregistrer efficacement les données des capteurs au fil du temps.

        \subsubsection{Activation de la puce PHY}
        \begin{lstlisting}[style=C, caption={Activation de la puce PHY}]
gpio_reset_pin(16); // Reset l'état du pin enable de puce PHY
gpio_set_direction(16, GPIO_MODE_OUTPUT); 

gpio_set_level(16, 1); // Applique une tension de 3.3v sur le pin Enable de la puce PHY pour activer l'horloge de 50MHz
        \end{lstlisting}

        La puce PHY (Physical Layer) est un composant essentiel dans les systèmes de communication numérique, servant d'interface entre les couches physiques d'un réseau et les couches de liaison de données.\newline
        Elle est responsable de la conversion des données numériques en signaux physiques qui peuvent être transmis sur un support de communication, tel qu'un câble ou une onde radio, et inversement.\newline
        La puce PHY gère également des fonctions telles que la modulation, la démodulation, la synchronisation et la correction d'erreurs, assurant ainsi une transmission fiable et efficace des données.\newline

        \newpage
        \subsubsection{Configuration de la MAC}
        \begin{lstlisting}[style=C, caption={Activation de la puce PHY}]
  eth_esp32_emac_config_t emac_config = ETH_ESP32_EMAC_DEFAULT_CONFIG(); // Configuration ethernet par défaut
  emac_config.clock_config.rmii.clock_mode = EMAC_CLK_EXT_IN; // Utilise l'horloge fournie par la puce PHY
  emac_config.clock_config.rmii.clock_gpio = EMAC_CLK_IN_GPIO; 

  eth_mac_config_t mac_conf = ETH_MAC_DEFAULT_CONFIG(); // Configuration MAC par défaut
  mac_conf.sw_reset_timeout_ms = 1000;

  esp_eth_mac_t *mac = esp_eth_mac_new_esp32(&emac_config, &mac_conf); // Nouvelle instance MAC
  ESP_LOGI("MAC :", "esp_eth_mac_new_esp32 done"); // Log
  eth_phy_config_t phy_config = ETH_PHY_DEFAULT_CONFIG(); // Configuration de la puce PHY par défaut
  phy_config.phy_addr = 1; // Adresse I2C de la puce PHY
  phy_config.reset_gpio_num = -1; // Pin reset de la puce PHY non relié

  esp_eth_phy_t *phy = esp_eth_phy_new_lan87xx(&phy_config); // Register type of PHY Chip
  if (phy != NULL){
      ESP_LOGI("PHY :", "esp_eth_phy_new_lan87xx done");
  } else {
      ESP_LOGE("PHY :", "esp_mac_phy_error");
  }
  esp_eth_config_t eth_config = ETH_DEFAULT_CONFIG(mac, phy); // Default ETH Config
        \end{lstlisting}


        Ce code configure la couche MAC (Media Access Control) d'un ESP32 pour une interface Ethernet.\newline
        Il commence par définir une configuration par défaut pour l'EMAC (Ethernet MAC) de l'ESP32, en spécifiant l'utilisation d'une horloge externe pour le mode RMII (Reduced Media Independent Interface) et en assignant un GPIO pour l'horloge.\newline

void mqtt_event_handler(void *handler_args, esp_event_base_t base, int32_t event_id, void *event_data)
{
    ESP_LOGD(TAG, "Event dispatched from event loop base=%s, event_id=%" PRIi32 "", base, event_id);
    esp_mqtt_event_handle_t event = event_data;
    switch ((esp_mqtt_event_id_t)event_id) {
    case MQTT_EVENT_CONNECTED:
        ESP_LOGI(TAG, "MQTT_EVENT_CONNECTED");
        CONNECTED = 1;
        break;
    case MQTT_EVENT_DISCONNECTED:
        ESP_LOGI(TAG, "MQTT_EVENT_DISCONNECTED");
        CONNECTED = 0;
        break;

    case MQTT_EVENT_PUBLISHED:
        ESP_LOGI(TAG, "MQTT_EVENT_PUBLISHED, msg_id=%d", event->msg_id);
        break;
    case MQTT_EVENT_DATA:
        ESP_LOGI(TAG, "MQTT_EVENT_DATA");
        printf("TOPIC=%.*s\r\n", event->topic_len, event->topic);
        printf("DATA=%.*s\r\n", event->data_len, event->data);
        break;
    case MQTT_EVENT_ERROR:
        ESP_LOGI(TAG, "MQTT_EVENT_ERROR");
        if (event->error_handle->error_type == MQTT_ERROR_TYPE_TCP_TRANSPORT) {
            ESP_LOGI(TAG, "Last errno string (%s)", strerror(event->error_handle->esp_transport_sock_errno));
        }
        break;
    default:
        ESP_LOGI(TAG, "Other event id:%d", event->event_id);
        break;
    }
}
